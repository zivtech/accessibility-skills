## Per-operation reasoning

### OP-ESC — dismiss the Details dialog with Escape

Full Shape 1 package. Every rule has a field to read.

- **`bounded_diagnostic_not_promoted`** — satisfied. Nothing bounded is being promoted. `action` is `Escape` (the documented exit itself, and the operation's own predicate), and `observed` reports what focus actually did afterward. This is the shape rule 1 *demands* of a trap/operability conclusion, arrived at from the other direction.
- **`setup_action_continuity`** — satisfied at the self-report tier the reference explicitly sets. `before.reached_by` is a continuous path in one sitting ("Loaded the results view, Tab ×5 …, Enter to open the Details dialog") with no reload or fresh load interposed; `before.locus` is a named AT position ("focus on its heading 'Item details'"), not "the page"; `action` starts from that locus; `session: 2026-09-02-JR-a` is present and single. The walk-through is candid that this equality is stated, not proven — I am admitting a structured self-report, not a verified identity.
- **`natural_only_conditional_state`** — not engaged. No conditional state is claimed; the dialog is reached by approved input (Tab, Enter). Nothing induced, nothing forced.
- **`passive_observation_binding`** — satisfied. `observed` ("Dialog closed; NVDA announced 'Renew, button'; visible focus ring on that button") is a genuine result of the Escape press: it is not a restatement of `expected`, not "works", not inspector-only. It carries two independent channels (announcement + visible focus ring) and `observed_via: announcement` is on the allowlist.
- **`ancestor_remapping_review`** — satisfied. `target_reached: exact`; no descendant reached through an owner.

Admitted. Disposition **PASS** — the observation decides the operation's predicate exactly as a trace would.

Two boundaries the package does not itself state, which belong in the claim boundary rather than in `rules_violated`:

1. **The n = 1 rule.** This PASS is one package. A fixed-stage PASS that will back a `supports` needs a second package — a different person (the control on expectation), or the same person in a separate session on a later day (which controls only session/environment variance) — with at least one of the two not the fix's author. Nothing in this evidence set is that second package: the only other session-bearing block (OP-LABEL) is the same person, same session, and is inadmissible anyway. So `rem-focus-return-2c7f0a1b` may **not** gain an `attestation` block on this record. This is not an admissibility rule, so it does not make the evidence inadmissible — the operation is PASS — but it caps what the PASS can be spent on.
2. **`version: "3.4.0"` is unverifiable here.** The reference requires it to equal the report's pinned version and to sit inside the evaluation window. No report, planned operation set, or window was supplied with this package, so I am admitting the field as well-formed, not as matched.

### OP-RETURN — focus return on the Renew dialog

Record in full: *"Checked the Renew dialog; focus return works fine now — J.R."* No `before`, no `action`, no `observed` result, no `session`, no `version`.

- **`setup_action_continuity`** — **violated.** There is no starting locus and no path to it, so rule 2's predicate cannot be shown at all. "Checked the Renew dialog" names a surface, not a control or AT position.
- **`passive_observation_binding`** — **violated.** "works fine now" is a verdict with no action for it to bind to, and no `observed_via`. Rule 4 has nothing to attach an observation to because no action was recorded.
- Rules 1, 3 and 5 have no field to read and are not violated — the record is too thin to make a claim any of them police. I am not padding the list.

This is the free-walk shape the reference refuses by construction, and the protocol names both rules for it by name. Rejected evidence never moves an operation; no prior recorded state was supplied.

**One tempting move to rule out explicitly:** OP-ESC's admitted evidence is also about focus return, on the same page, in the same session, and its `observed` even names a "Renew" control. It does not carry OP-RETURN. OP-ESC's target is the *Details* dialog; OP-RETURN is stated as a second, distinct finding on the *Renew* dialog; and OP-ESC's own `claim_boundary` says "Nothing about other dialogs." Letting one dialog's trace stand in for another's is the ancestor-substitution error in a different coordinate. Disposition **UNTESTED**.

### OP-AD — audio description track for the training video

Shape 2 (attended media, `17.E`-class content observation). Rules 2 and 5 are marked not applicable to this shape — no locus, no action, no descendant reached through an owner — so they cannot be violated here, and the media-identity analogue of rule 5 is satisfied in that the asset ("the training video") is at least named.

- **`passive_observation_binding`** — **violated.** This is the rule that does the whole binding load in Shape 2, and this record is its textbook failure: a **menu listing** offered as evidence that the alternative exists. `played` is the binding field and it is absent by the package's own admission — "Nothing was played and nothing was heard." A menu entry, a track label, or a player's "described" badge never stands alone as evidence that a description track exists, let alone that it is adequate.
- **`bounded_diagnostic_not_promoted`** — I considered flagging this, since a bounded observation ("menu lists a track") is being dressed as a PASS conclusion. I am not listing it. The protocol assigns this exact catch to rule 4 ("rule 4 is what catches a menu listing or a track label offered as evidence of the alternative"), and adding rule 1 on top would double-count one defect rather than name a second one.
- **`natural_only_conditional_state`** — not engaged; nothing was staged.

**Disposition: UNTESTED, not BLOCKED.** This is the discriminating call in this package and I want to show the work. BLOCKED requires an *admitted* bounded observation about the operation standing without the trace or instrument that would decide it — "I watched the animation and cannot count flashes per second", "captions seemed late". Both of those were **attended**: something was played, watched, or listened to, and only the instrument is missing. Here nothing was attended. The walk-through's own parenthetical is exactly this fork — "a bounded observation with no played stretch behind it is `BLOCKED` (or `UNTESTED` if nothing was attended)" — and "nothing was played and nothing was heard" lands on the second branch. The confirming test is remediation shape: BLOCKED obliges `claim_boundary` to name the instrument that would close it, and there is no instrument to name. What this operation needs is a play button and headphones, which is the definition of nobody having looked. Collapsing that into BLOCKED would launder an unperformed observation into an instrument limitation.

### OP-OPTION — nested option state inside the filter combobox

Record in full: *"Tabbed to the filter and the highlighted option's selected state looked right — J.R."*

- **`ancestor_remapping_review`** — **violated**, and this is the headline. The person reached the **combobox owner** ("the filter") and reports on a **descendant** (the highlighted option's selected state) with no mapping cited. Rule 5 admits ancestor-recorded evidence only through a reviewed, separately frozen owner/descendant mapping named on the record as `ancestor: <owner>, mapping <ref>`; a silent nearest-ancestor substitution is not evidence about the target. This is the reference's own worked example of the failure.
- **`passive_observation_binding`** — **violated independently.** Two distinct defects, not one restated: (a) "looked right" is the banned verdict class — an `observed` that restates the expectation or says only "works"/"as expected" is not an observation; (b) more seriously, the state being reported has **no causing action at all**. `Tab` reached the filter; nothing on the record says which key press produced the highlight or the selection whose state is being judged, and no `observed_via` is given. A visual impression of a state with no key press behind it is precisely the passive observation rule 4 forbids from standing alone.
- **`setup_action_continuity`** — I am **not** flagging this, and I want to be explicit that it is my least confident line. The record has no `session` field and no `reached_by` path, which is a real shape defect. But the protocol's discriminator for the rule-2 failure is "no starting locus and no action" — and unlike OP-RETURN, this record does supply a named control as a locus ("the filter") and a stated action ("Tabbed"). No discontinuity is demonstrated; a field is missing. I would rather under-list a rule I would only argue at even odds than inflate the violation set, since `rules_violated` is read mechanically. A reviewer who listed `setup_action_continuity` here would not be wrong on the missing `session`, and I flag that as the seam in this disposition.
- Rules 1 and 3 are not engaged.

Rejected evidence never moves the operation, and nothing else in the package bears on the option's selected state. Disposition **UNTESTED**.

### OP-LABEL — accessible name of the row-action button

Every field is present and well-formed: `session` matches OP-ESC's, `before.reached_by` is a continuous path, `before.locus` is a named control ("the first row-action control, before the 'Renew' control"), `action: Tab` starts from that locus, `observed_via: announcement` is allowlisted, `target_reached: exact`. Rules 1, 2, 3 and 5 all have their predicates shown.

- **`passive_observation_binding`** — **violated, and alone.** `observed: "As expected"` is not an observed result of the action; it restates `expected` and adds nothing. The whole point of this operation is *what NVDA actually said*, and the one field that would carry it is empty of content. This is the tidier failure the protocol names: every field filled, no observation bound to the action. No sixth rule is needed — the shape gave rule 4 something to read, and what it reads is a blank.

The verbatim-announcement discipline is what makes this rule bite: `before.announced` records "button" verbatim as heard, which is exactly the fidelity `observed` abandons. A record that can quote the *pre*-action announcement and cannot quote the post-action one is self-evidently not reporting an observation.

**A second tempting move to rule out.** OP-ESC's admitted `observed` line contains `NVDA announced 'Renew, button'` — an announcement of a Renew button's accessible name, bound to a real action, `observed_via: announcement`, `target_reached: exact`. It is fair to ask whether that admitted observation decides OP-LABEL. It does not, for two reasons. First, target identity: OP-ESC's `before` reaches "the 'Renew' row action" by Tab ×5 without naming a row, while OP-LABEL's target is the **first** row's Renew control reached by Tab ×4 to the action group. Inferring they are the same control is an unrecorded ancestor/sibling substitution — the same class of move rule 5 exists to refuse. Second, scope: OP-ESC recorded that announcement as the *evidence of focus landing*, and its `claim_boundary` scopes the package to focus return on that dialog. Borrowing it sideways to close a name finding is exactly the silent rescoping the claim-boundary mechanism is there to prevent. I note the near-miss rather than spend it.

Disposition **UNTESTED** — not BLOCKED, because what is missing is an observed result the person was in a position to record, not an instrument reading no human attendance could supply.
