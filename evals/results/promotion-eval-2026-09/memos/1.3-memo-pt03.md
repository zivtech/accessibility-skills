# Memo: engagement ledger-builder vs. baseline-url-scan.mjs resume/coverage fold-in

## 1. What the ledger builder does

Source: private repo, `evidence/harness/build-detector-resumption-ledgers.mjs` (360 lines). It does **not** scan URLs itself — it is a downstream aggregator that reads 6 already-produced evidence documents for one engagement's product-A (structured-sample corpus, random-population + selection receipt, interactive-ranking, complete-processes, plus two named third-party detector receipts) and a manifest/anchor verification gate, and emits 3 static coverage/adjudication ledgers.

There is no per-URL scan-skip logic anywhere in this file — the name is aspirational relative to what it does.

## 2. Separability into baseline-url-scan.mjs

**Cleanly separable as a *pattern*, not as code.** Nothing in the private script ports — it aggregates over engagement-specific documents and a manifest/anchor gate the public repo has no analog for. The `--resume` + `coverage` block described in the brief must be designed fresh against baseline-url-scan.mjs's own per-URL loop:

- `parseArgs` (208-235): add `--resume` boolean flag near the existing flag branches (218-223).
- New helper (none exists yet), called from the per-URL loop (63-68) before `scanUrl` (90): check the per-URL JSON at `path.join(outDir, slug(url,index)+'.json')` exists, is parseable, and `record.status === 'measured'` (100) — see guard in §4 — then push it and mark it resumed instead of calling `scanUrl`.
- `buildSummary` (153-206): add a `coverage` object beside `totals` — `{ measured, aborted: {count, by_reason}, skipped_resumed }` — derived from each record's `status`/`error` (100, 132) and the new resumed flag. `by_reason` needs a reason classifier that doesn't exist yet (today `record.error` is just `String(error.message).slice(0,2000)`, line ~133).
- `schema_version` bump: '1.2' (188) → '1.3'.

## 3. What SKILL.md already promises (would become machine-true)

> "An infrastructure limit must never emit a canonical result... record it as what it is (aborted, incomplete, environment-limited) and keep it out of the pass/fail denominator until it is resolved." (SKILL.md:59)

> "Mandatory cross-check rule: whenever a run's non-conclusive rate... approaches saturation for a batch... treat that as a signal about the collector, not about the product." (SKILL.md:61)

Today `totals` (188-198) reports raw `measured`/`errors` counts with no rate at all — nothing enforces line 59's denominator rule mechanically; a downstream consumer could still divide by `urls_scanned` instead of `measured`. A `coverage` block with `aborted` split out (and `by_reason`) makes the exclusion legible and checkable rather than merely possible.

## 4. Negative space — resume must NOT

Must not silently reuse a cached per-URL result captured under a different axe-core version or viewport set. Guard before treating any cached file as reusable:
1. `record.status === 'measured'` only (not `'partial'`/`'error'`) — a cached partial/error record must force a rescan.
2. Compare `Object.keys(record.viewports)` against the currently-requested viewport keys from `parseViewports()` (236) — exact match required, not subset.
3. Compare each viewport's recorded `axe_core_version` (line ~118) against the currently-resolved/pinned version — mismatch forces rescan.
4. If `--census` or `--alt-snapshot` is requested now but the cached viewport record lacks `census`/`alt_snapshot` keys, force a rescan for that URL rather than reporting partial data as complete.

## 5. Mutation canaries

1. Drop the axe-core-version check → canary: bump the pinned version between runs, assert a `--resume` rerun rescans (not skips) affected URLs.
2. Weaken viewport-set check to subset-match → canary: add a third viewport not in the cached file; assert rescan, not a silently-missing viewport.
3. Drop the `status === 'measured'` gate → canary: seed a cached file with `status: 'error'`, run `--resume`, assert rescan (not counted as `skipped_resumed`).
4. Fold `aborted` into a rate numerator/denominator → canary: seed one aborted + one measured URL, assert no summary field computes a rate over `aborted` (SKILL.md:59).
5. Ignore `--census`/`--alt-snapshot` cache mismatch → canary: cached record has no `census` key, rerun with `--resume --census`, assert rescan produces fresh census data rather than a silent gap.

## 6. Disposition

**FOLD-INTO(baseline-url-scan.mjs)** — effort **M**. The concept is sound and buildable in ~2 new functions plus edits to 3 existing ones (`parseArgs`, main loop, `buildSummary`) and a schema bump; nothing from the private script itself is portable (it's a fixed-inventory aggregator over engagement-specific, hardcoded-ID documents plus a manifest/anchor gate this repo has no equivalent for). The version/viewport/flag-parity guards in §4 are real, non-trivial design work — that's what pushes this past S.
