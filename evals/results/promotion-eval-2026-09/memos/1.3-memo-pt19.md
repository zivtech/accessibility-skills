## Q1 — Violations / conformance (builder ↔ skill ↔ scorer), all cited by line

1. **INCOMPLETE marker stem — CONFIRMED FAIL.** Builder:115/121 emits `INCOMPLETE DRAFT: untested A/AA criteria: <list>.` (colon). Skill:130 requires `INCOMPLETE DRAFT — untested A/AA criteria: <list>` (em dash). Scorer:61-62 `INCOMPLETE_RE = r"INCOMPLETE DRAFT\s*[—–-]+\s*untested A/AA criteria:"` requires a dash-class char, not `:`. Ran the regex against the actual generated `product-a-interim-draft.yaml` notes field (empirically, not from the fixture harness): **match = False**. Scorer:463-464 would fire `must_miss "document notes lack the INCOMPLETE DRAFT marker + gap list"` → FAIL. One-character-class fix.
2. **Single hardcoded reason for every SC — plausible FAIL.** Builder:41 `incompleteReason` is one literal string, applied identically to all 56 A/AA criteria (builder:74 `reason: incompleteReason` in the JSON spine; yaml notes:117 one blanket sentence, not per-SC). Skill:131 requires "the same list with **a per-SC reason**"; skill:134 further requires distinguishing categories (not sampled / tooling gap / ran out of scope / no access / needs a human owner). Scorer:480-483 checks per-SC by grepping handoff lines containing each SC token for reason tokens (`sc_lines` + `any_token`) — a shared blanket sentence not co-located with each SC citation would very likely miss this per-SC check for most SCs (I could not run this specific check without a fixture's `reason_tokens`, so this is PLAUSIBLE not CONFIRMED).
3. **Hardcoded author/company/email/roles/product names — mixed.** Builder:17-21 hardcodes `author.name/company_name/email` (hardcoded author name/email) and builder:43-58 hardcodes product-A/product-B names/descriptions/titles directly in the script (no input-file provenance) — not itself a skill violation (skill:32/55 just requires values "trace to the engagement record," doesn't forbid literal scripting), but it means the script is a one-off, not a reusable generator (relevant to Q2/Q4). **Roles are compliant**: builder:86-88 correctly labels the draft author and evaluation sponsor `[Demo Purposes Only]` and leaves exactly one non-demo identity ("Tester", a hardcoded tool-name string) — matches skill:163-169 exactly.
4. **`not-evaluated` AAA-only — OK, verified compliant.** Builder:101-107 (spine) and :123-131,158-162 (yaml, `success_criteria_level_aaa` chapter) apply `not-evaluated` only to the AAA chapter; all A/AA criteria are omitted from `chapters` entirely rather than marked `not-evaluated` (builder:152-157 — chapters carry only a `notes:` key, no `criteria:`). Matches skill:88,109,120,132 and the scorer's illegal-term check (score_acr.py:308-314) would find zero hits.
5. **Disabled non-web 508 chapters — OK, verified compliant.** Builder:163-178 sets `disabled: true` on all four non-web chapters with notes starting `Outside the web evaluation method's coverage:` (builder:40 `coverageBoundary`) — byte-identical to `DISABLED_STEM` (score_acr.py:60) and skill:121's canonical form. Scorer's chapter-policy check (score_acr.py:518-529) would pass.
6. **`evaluation_methods_used` / `legal_disclaimer` — likely OK, unverifiable against a live fixture.** Builder:146-147 states "WCAG-EM 2.0" but honestly omits a sample count (none is frozen yet) rather than fabricating one — consistent with skill:177's intent though it doesn't match the skill's complete-draft example literally. `legal_disclaimer` (builder:148-149) states "not a legally binding conformance claim... not... authorization to publish" — satisfies skill Non-Negotiable #4 (skill:240) and checklist:263.
7. **License absence — surfaced in notes, handoff artifact not reviewed.** Builder yaml() emits no `license:` key (confirmed: `grep -n "^license" product-a-interim-draft.yaml` → none) → schema defaults to CC-BY-4.0 (skill:215). Builder:121 notes line does say "No license decision has been supplied; this draft is not authorized for publication" — partially satisfies skill:225's "surface it in the handoff," but these two scripts don't produce a separate handoff message, so full compliance is unverifiable from source alone.
8. **CLI-validity of omitting all A/AA from `chapters` — CONFIRMED VALID.** Ran the pinned `@openacr/openacr@0.3.8` CLI (`npx openacr validate -f product-a-interim-draft.yaml -c .../2.5-edition-wcag-2.2-508-en.yaml`) against the actual builder output: **`Valid!`**, both with and without `-c`. Confirms skill:129's claim that chapter-omission "stays CLI-valid" — this is the documented, correct pattern for a wholly-untested draft, not a defect.
9. **HTML postprocessor — not addressed by the skill (gap, not a violation).** `postprocess-openacr-html.mjs` rewrites the CLI-rendered HTML in place (`<th scope="col">`, td→th `scope="row"` conversion, `aria-hidden`+`tabindex=-1` on header anchors, injected target-size/reflow CSS) and overwrites the source `openacr/*.html` file (line 23), so the "rendered HTML" in the handoff (skill checklist:267) is no longer byte-identical CLI output. The skill is silent on post-render HTML patching; this is an unaddressed boundary, not a cited violation.

## Q2 — Generic input-spine shape (≤30 lines)

```yaml
schema_version: "1.1.0"
engagement:
  report_title: string            # engagement record, never hardcoded in script
  product_name: string            # engagement record
  catalog: string                 # decided at planning time (skill Catalog Selection)
  report_date: string             # evaluation completion date, not "today"
  author: {name, company_name, email}   # author.email hard-required
  roles:                          # exactly one non-demo identity: tester
    - {role: draft_author, name, email, demo_label: true}
    - {role: evaluation_sponsor, name, demo_label: true}
    - {role: tester, name, demo_label: false}
  license: string|null            # null -> surfaced in handoff, never CC-BY assumed silently
  legal_disclaimer: string        # mandatory draft language
  coverage_boundary: string       # DISABLED_STEM-form non-web boundary note
criteria:                         # one row per catalog A/AA/AAA SC, no silent drops
  - sc: "1.1.1"
    level: A
    outcome: passed|failed|cantTell|inapplicable|untested|not_evaluated
    reason_category: not_sampled|tooling_gap|ran_out_of_scope|no_access|needs_human_owner  # required iff untested
    reason_detail: string         # per-SC, never shared across SCs
    finding_ids: [string]         # required for failed/partially
    sample_ids: [string]
```

## Q3 — Does the report contract's outcome map already cover this?

Partially. `docs/a11y-evaluation-report-contract.md:11` (ACR-feed fields) gives report title, product name+version, evaluator email, feedback channel; `:18` (`outcomes`) gives per-SC EARL outcome; `:19` (`findings`) gives `finding_id`s; `:20` (`coverage_boundary`) gives the non-web boundary text. **Missing, all ACR-only:** (a) `catalog` id — not a report-contract field at all; (b) the 5-category untested-reason vocabulary (not_sampled/tooling_gap/ran_out_of_scope/no_access/needs_human_owner) — the report contract has no reason taxonomy, only the EARL outcome; (c) chapter/component policy (web-only vs. `disabled:` non-web chapters) — ACR-specific, not in the contract; (d) role display metadata + `[Demo Purposes Only]` convention — ACR-only (skill:163-169); (e) `legal_disclaimer` text — ACR-only (report contract's closest analog, `honest_boundary`, is a different concept); (f) license decision — absent from the report contract entirely.
