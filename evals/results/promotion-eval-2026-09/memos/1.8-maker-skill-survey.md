# Maker/community skill survey: WAVE API and Alfa (before building a routed adapter)

Question: does a skill, plugin, or official client already exist for (1) WebAIM's WAVE
API and (2) Siteimprove's Alfa engine, from the makers or the community?

## Method / positive controls

- skills.sh: used the `npx skills find <term>` CLI (confirmed live, no auth needed —
  the underlying search endpoint `GET /api/v1/skills/search` requires a Vercel OIDC
  token when hit directly via curl, but the CLI handles auth transparently).
  Positive control: `npx skills find accessibility` returned 19 real hits (e.g.
  `addyosmani/web-quality-skills@accessibility`, `anthropics/knowledge-work-plugins@accessibility-review`,
  `mgifford/accessibility-skills@manual-testing`) — proves the search path works.
- GitHub: `gh search repos` / `gh search code` (live, returned real results for
  unrelated control queries like "accessibility mcp server").
- npm: `registry.npmjs.org/-/v1/search` + `api.npmjs.org/downloads/point` (live).

## A/B/C — WAVE (WebAIM)

**Maker-published:** None found. `wave.webaim.org/api/` and `/api/details` confirm a
credit-based hosted API (100 free credits on signup; 1 credit/page basic, 2-3 for
advanced; volume pricing $0.04→$0.025/credit) and a separately-licensed Stand-alone
API (on-prem, ~$4,000-$12,000+/yr per secondary search-result pricing tables — not
independently confirmed via WebAIM's own pricing page). No official SDK, npm package,
CLI, GitHub Action, MCP server, or Claude/Codex skill is mentioned on any WAVE API
doc page. **The WebAIM GitHub org (`github.com/WebAIM`) has 0 public repositories**
(`gh api orgs/WebAIM` → `public_repos: 0`) — confirmed zero-hit, not a search miss.

unrelated fuzzy/semantic noise — a wordplay-name design skill, a wifi-pentest skill,
podcast tooling). `gh search repos "wave mcp accessibility"` → `[]`. No MCP server
wrapping WAVE was found anywhere (GitHub or skills.sh).

**Recommendation (WAVE):** Nothing satisfies the bundle's boundary. The two
JS-ecosystem clients are both sub-1.0, low-adoption, single/few-maintainer packages
(one 3 years stale, one released mid-2025 with no repo visibility) — neither is a
"routed, exact-pinned, detector" candidate as-is; either would need a fresh audit
before pinning. A routed adapter, if built, would be writing directly against
WebAIM's REST API rather than reusing an existing client, since WebAIM itself ships
none.

## A/B/C — Alfa (Siteimprove)

**Maker-published:**
- `github.com/Siteimprove/alfa` — the open engine itself. MIT licence (Siteimprove
  A/S). ACT-Rules-based conformance testing engine producing EARL output. 131
  stars / 17 forks / 92 open issues at time of check.
- `github.com/Siteimprove/alfa-integrations` — official integration packages, all
  MIT: CLI, scraper (`alfa-scraper`), crawler (`alfa-crawler`), test-utils, and
  per-tool adapters (Cypress, Playwright, Puppeteer, WebdriverIO, Angular, React,
  Vue, jQuery, Cheerio, Chai, Jasmine, Jest, Selenium, Unexpected, Vitest). Per the
  repo's own README, **only Cypress/Playwright/Puppeteer/WebdriverIO are actively
  maintained** (as the engine behind the commercial Accessibility Code Checker);
  the rest are marked experimental/subject to change.
- `@siteimprove/alfa-rules` (npm) — MIT, actively published (v0.119.0, 2026-07-22),
  9,277 downloads/month — the healthiest, most current package in this whole survey.
- Accessibility Code Checker (`alfa.siteimprove.com/code-checker`) — Siteimprove's
  own commercial-facing product built on Alfa, CI/CD-integrated (Cypress, Playwright,
  Puppeteer, Selenium), with AI remediation suggestions. Licensing/pricing terms
  were **not confirmed** — the Introduction, Getting Started, and public docs pages
  fetched did not state whether it's free or requires a paid Siteimprove account;
  flagging as unresolved rather than guessing.
- No official MCP server, Claude Code skill, or Codex skill from Siteimprove was
  found anywhere (GitHub, skills.sh, or Siteimprove's own site).

Zero hits: skills.sh for "alfa" and "siteimprove" returned no on-topic result (only
unrelated wifi-security and design skills, plus a self-referential fuzzy match to
this repo's own `zivtech/accessibility-skills@bug-reporting` — noise, not a finding).
`gh search code "alfa mcp accessibility"` → `[]`. `gh search repos "wave api
accessibility"` and `"webaim wave"` overlap-checked as controls for the WAVE side.

**Recommendation (Alfa):** Reuse, don't build fresh — but reuse the *maker's own*
packages, not a community wrapper. If a routed adapter is warranted, the natural
integration point is `@siteimprove/alfa-playwright` or `@siteimprove/alfa-puppeteer`
from `Siteimprove/alfa-integrations` (both explicitly "actively maintained," MIT,
and match this bundle's existing Playwright-first testing lane) or the `alfa`
CLI/`alfa-rules` package directly — exact-pinned like every other routed dependency
in this repo. No community MCP/skill adds value here; the one community MCP server
found (siteimprove-mcp) wraps the wrong surface (paid platform API, not the open
engine) and has no licence.
