## (a) Draft skill-text addition (≤15 lines)

Insert as a new subsection immediately after the fifth bullet and before the
blank line at `.claude/skills/a11y-test/SKILL.md:99-100` (i.e. between the
existing "No silent ancestor remapping" bullet and the `### PASS partition`
heading at line 101). Matches the section's own voice (bold lead clause,
terse declarative follow-on, back-reference to the eval suite already used at

```
### Structured disposition block

Every admissibility review closes with one fenced yaml block a rule-based
scorer checks mechanically (the `score_acr.py` precedent). Stable ids for
the five rules above: `bounded_diagnostic_not_promoted`,
`setup_action_continuity`, `natural_only_conditional_state`,
`passive_observation_binding`, `ancestor_remapping_review`.

    admissibility: ACCEPT | REJECT
    dispositions: {<operation id>: PASS | FAIL | UNTESTED | BLOCKED | INADMISSIBLE}
    rules_violated: [<rule id>, ...]   # empty only when admissibility: ACCEPT
    claim_boundary: <what this block asserts, and does not assert, about the package>

This block scores the evidence package's admissibility, not the target's
accessibility.
```

15 content lines (excluding the blank separators and the fence markers used
only for display in this memo). `claim_boundary` as a bare `<field>: <one
line>` scalar matches the idiom the register already documents at
`docs/a11y-orthogonality-register.md:20` ("a `claim_boundary` field carried
on the adjudication or finding record itself... what the entry does and
does not assert") — lighter than acr-reporting's prose-paragraph use of the
same field (`.claude/skills/acr-reporting/SKILL.md:99`) because this block
is machine-parsed, not a human-readable ACR note.

## (b) Metadata key → mechanical check map

| Metadata key | Tier | Mechanical check | Needs |
|---|---|---|---|
| `expected_admissibility` (all 3 fixtures) | must | `yaml.admissibility == meta[key]` exact string match | yaml block |
| `expected_dispositions` (op-retest-clean only, `RUBRIC…op-retest-clean.metadata.yaml`) | must | `yaml.dispositions[op_id] == want` per op id | yaml block |
| `expected_coverage_must_stay` (op-empty-state…, scalar `UNTESTED`) | must | **cannot be mechanically checked as shaped** — see below | — |
| `must_catch[].id` (all BUG fixtures, 2+3 ids) | must | `id in yaml.rules_violated` | yaml block |
| `must_catch[].hook_present` | should | `any_token(prose, tokens)` on the yaml-fence remainder (the `score_acr.py:99` `extract_..._yaml` remainder pattern) | prose |
| `must_catch[].hook_absent_in_evidence` | n/a | **cannot be mechanically checked against the response** — see below | — |
| `expected_verdict_must_not` (all 3 fixtures) | must (fabrication-class) | phrase absent from `strip_negation_lines(prose)` (promoted helper, see (d)) | prose |
| `nice_to_have` | nice | `any_token`, printed, never gates status | prose |

Two keys flagged:

- **`expected_coverage_must_stay: UNTESTED`** (`fixtures/op-empty-state-coverage-shortcuts.metadata.yaml`) is a bare scalar with no operation id attached — the comment ("both operations remain untested") is the only place the scope lives. It cannot be parsed into a per-operation assertion as shaped. **Extend, don't delete**: rename to `expected_dispositions: {OP-EMPTY: UNTESTED, OP-OPTION: UNTESTED}`, unifying the key op-retest-clean already uses (`rubrics/op-retest-clean.metadata.yaml` shows the working shape). One-line metadata edit, no scorer special-casing needed.
- **`must_catch[].hook_absent_in_evidence`** (e.g. `["Escape", "exit-path", "exit path"]` on `bounded_diagnostic_not_promoted`) documents what is absent from the *fixture's own evidence package* — it is prose about the input, not a property the model's response could satisfy or violate. Wiring it as a response check would be measuring the wrong artifact. Recommend: leave it unwired, unscored, fixture-documentation-only — do not delete (it's load-bearing for a human reading the fixture to understand *why* the rule fires) and do not repurpose it as a response check (that would require the reviewer to recite specific absent tokens, which rewards phrasing over judgment — the same trap `known_judgment_calls` in every rubric already warns against).

## (c) Mutation-canary set

asserts" resolution already implied by each fixture's `expected_*` fields,
plus 3–5 prose lines), then one single-dimension mutation per must-tier key.
Naming: `evals/suites/smoke/opevidence-<fixture-slug>-<variant>-response.json`.
Gold assertion in every case: `Status: PASS`. Every mutation asserts
`Status: FAIL` plus the specific must-miss line the scorer would print
(f-string style matched to `score_acr.py:237-238`,
`must_miss.append(f"...")` → printed as `  - ...`).
