# Maker/community survey: XLSX finding-workbook builders (PT-18)

Before building a reference script that serializes accessibility bug-report findings (one JSON object per finding: url, xpath, html_snippet, wcag_sc, rule_id, severity, frequency, instance_id...) into an XLSX workbook for client triage, does an existing skill, MCP server, CLI, library, or integration already do this?

## Method / positive controls

- `npx skills find <term>` — non-interactive by piping `< /dev/null` and wrapping in `perl -e 'alarm 20; exec @ARGV'` (no `timeout`/`gtimeout` binary on this machine). Positive control `npx skills find accessibility` returned 20+ real hits (addyosmani/web-quality-skills@accessibility, anthropics/knowledge-work-plugins@accessibility-review, mgifford/accessibility-skills@bug-reporting, etc.) — CLI works non-interactively when stdin is `/dev/null`.
- npm registry: `curl -s "https://registry.npmjs.org/-/v1/search?text=<q>&size=20"`, piped through `python3 -c "import json..."` for name/version/date/description.
- Download counts: `curl -s "https://api.npmjs.org/downloads/point/last-month/<name>"`.
- `gh search repos "<phrase>"` (exact-phrase quoting returned `[]` for every multi-word accessibility+xlsx phrase tried — GitHub's search API does not do phrase-AND well on quoted multi-term queries); re-run as unquoted space-separated terms, which returned real hits. Positive control: `gh search repos axe exceljs` returned a live hit (roshan9029/playwright-axe-accessibility-framework), confirming the search itself works.
- `gh search code "term1" "term2" --limit 20` for exceljs + axe-core co-occurrence — worked, returned real hits.
- `gh search code "<term>" --repo <owner/repo>` for spot-checking whether specific vendor repos (microsoft/accessibility-insights-web, w3c/wcag-em-report-tool, dequelabs/axe-core) contain xlsx-related code.
- Vendor docs: `curl -sL <url>` + grep for csv/xlsx/excel/export keywords; two vendor sites (deque.com axe DevTools page, accessibilityinsights.io reports doc) returned JS-rendered shells or 404s and yielded no usable text — noted as unverified below rather than guessed.
- Advisories: `gh api "/advisories?ecosystem=npm&affects=<name>&per_page=10"`.
- SheetJS npm-vs-CDN: `curl -sL https://docs.sheetjs.com/docs/getting-started/installation/nodejs` grepped for `cdn.sheetjs.com` / version strings.

## Zero hits

- `gh search repos "accessibility xlsx report"` — zero. Positive control: `gh search repos axe exceljs` (unquoted) returned a live hit, confirming the search mechanism works; the quoted multi-word phrase form is what returns empty, not a broken query path.
- `gh search repos "axe-core excel"` — zero, same positive-control caveat as above.
- `gh search repos "a11y findings spreadsheet"` — zero, same caveat.

- `gh search code "xlsx" --repo microsoft/accessibility-insights-web` — zero hits (positive control: the same repo returns real hits for `ReportExportFormat`, confirming code search against this repo works).
- `gh search code "xlsx"` / `"csv"` `--repo w3c/wcag-em-report-tool` — zero hits both.

- Siteimprove/Alfa README grepped for csv/xlsx/excel/export/sarif/earl — zero hits on the spreadsheet-format terms specifically (earl is the format Alfa actually uses, confirmed present elsewhere in the README).

## Recommendation

No maker or community tool does the specific job this task needs: taking the bug-reporting skill's finding schema (url, xpath, html_snippet, wcag_sc, rule_id, severity, frequency, instance_id) and serializing it straight to XLSX for client triage. The one true maker hit — IBM's `accessibility-checker` (Apache-2.0, actively published) — does ship an open-source XLSX exporter, but it's wired to IBM's own axe-based result schema, not this skill's finding contract; it's worth a source read (not a re-run) before writing serialization logic from scratch, since its column-mapping choices may be directly reusable. Every other vendor exporter surveyed (axe DevTools, Accessibility Insights, pa11y, Alfa, Lighthouse, WAVE, WCAG-EM Report Tool, OpenACR) tops out at CSV/JSON/HTML/EARL/YAML — none emit XLSX, or in WAVE's case aren't open source regardless. If building, **`exceljs` (MIT, 55M downloads/mo)** is the safer library choice over SheetJS's npm `xlsx` package, whose latest npm release (0.18.5, from 2022) sits below the fix versions for two HIGH-severity advisories (ReDoS, prototype pollution) — SheetJS's own docs now point installs at their CDN instead of npm. `write-excel-file` is a lighter, actively-maintained alternative if styling needs are minimal. Could NOT be independently verified: axe DevTools' actual export format list (vendor doc pages 404'd/JS-rendered), and the precise mechanics behind WAVE's "Excel spreadsheet" report link (API docs endpoint returned live rule JSON, not stable documentation).
