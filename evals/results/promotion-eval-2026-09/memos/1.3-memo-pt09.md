## 2. Minimal generic rule set (target 6-10)

1. Every structured sample has a stable unique identity key and a non-empty rationale naming what it represents (template / functionality / technology / shared component).
2. `count(random) >= ceil(0.10 * count(structured))`, and `random ∩ structured = ∅` by identity key.
3. `sample_set.random_selection_method` is a non-empty documented string (method, not necessarily determinism receipts).
4. Every sample lists ≥1 state (default/loading/error/expanded, etc.); state list non-empty.
5. `≥1 complete_process` entry with `≥1 branch_sequence` (default + a named critical branch) **or** an explicit `none_reason`.
6. `environment_matrix` is non-empty and each row names ≥1 browser, ≥1 AT (or "n/a" explicit), and ≥1 viewport.
7. `representativeness_check` is present with a boolean/enum outcome and, if `surfaced_new=true`, a `structured` expansion note.
8. If `sampling_skipped=true` (whole product evaluated), all of 2-3 are waived but rule 7 and 4 still apply per view.
9. Freeze: `status == "frozen"` requires `frozen_at` and `frozen_by` both present; else validator exits non-zero.
10. All of 1-9 hold simultaneously for `valid=true`; any single failure → non-zero exit with a listed error code.

## 3. Proposed YAML shape (`sample_set` appendix example)

```yaml
sample_set:
  status: frozen              # draft | frozen
  frozen_at: 2026-09-02T00:00:00Z
  frozen_by: "J. Reviewer"
  sampling_skipped: false     # true only if whole product evaluated
  structured:
    - id: str-01
      represents: "product listing template"
      canonical_url: "https://product-a.example/listings"
      states: [default, loading, empty]
  random:
    method: "randomized sample of 10% of structured, drawn from unselected routes"
    items:
      - id: rnd-01
        canonical_url: "https://product-a.example/detail/9"
        states: [default]
  representativeness_check:
    outcome: no_new_content_types   # no_new_content_types | surfaced_new
    surfaced_new_notes: ""
  complete_processes:
    - id: proc-01
      starting_point: "https://product-a.example/start"
      default_sequence: [str-01, rnd-01]
      branch_sequences:
        - name: "error re-entry"
          sequence: [str-01]
      none_reason: null
  environment_matrix:
    - browser: chromium
      assistive_tech: none
      viewport: "1280x800"
    - browser: safari
      assistive_tech: voiceover
      viewport: "1280x800"
```

## 4. Mutation canary (per rule, single-field mutation that must be rejected)

1. Drop `structured[0].represents` → empty rationale → must fail.
2. Set `random.items` count to `floor(0.10*n) - 1` → below-threshold → must fail.
3. Duplicate a structured `canonical_url` into `random.items` → overlap → must fail.
4. Blank `random.method` string → must fail.
5. Remove `states` array from one structured item → empty-states → must fail.
6. Remove `branch_sequences` and `none_reason` from a `complete_processes` entry → must fail.
7. Empty `environment_matrix: []` → must fail.
8. Flip `representativeness_check.outcome: surfaced_new` with empty `surfaced_new_notes` → must fail.
9. Set `sampling_skipped: true` with a non-empty `random.items` and no override note → ambiguous state → must fail (or require explicit waiver field).
10. Set `status: frozen` and delete `frozen_by` → must fail.

## 5. What the engagement family does that should NOT be generalized

- sha256-seeded deterministic replay of random selection (validate-phase1.mjs:592-598) — reproducibility receipt overkill for a report-contract appendix; WCAG-EM only requires the method be *recorded*, not cryptographically replayable.
- Fixed 20-selected/≥3-alternate portfolio sizing (validate-phase1.mjs:364-365) — an engagement-specific staffing/scope decision, not a sampling-adequacy rule.
- Weighted 7-factor prioritization scoring (validate-phase1.mjs:34-43) — page-selection *rationale mechanism*, not part of what makes a frozen sample set valid.
- Named product ID allowlist (validate-phase1.mjs:48, 713-733) — engagement-specific denominator; a generic validator should take products/scope as input, not hardcode them.
- Full charter (commissioner/audit-owner/operator confirmation) and substitution-ledger workflow (validate-phase1-charter.mjs, validate-phase1-substitutions.mjs) — adjacent engagement-management concerns, out of `sample_set` shape entirely.
- Owner-only-file/symlink/SHA-256-receipt evidence-binding machinery threaded through nearly every check — belongs to this harness's evidence-contract, not to a sample-set schema validator.

## 6. Effort and confidence

- Effort for a ~150-line `validate-sample-set.mjs` implementing rules 1-10 above: **S** (single-file, no cross-ledger joins, no crypto, no receipt I/O — closer to a schema+predicate checker).
- Confidence is **low** on: (a) whether `representativeness_check` should be a `sample_set` field at all vs. an `outcomes` field per the report contract (L18 currently ties it to `outcomes`, not `sample_set` — I read the row split from the doc grep only, not full prose); (b) exact wording WCAG-EM expects for "commonly-accessed critical branch" vs. a bare `none_reason` — I have only the verified-reference bullet (wcag-em-2-reference.md:64), not the full Step 3.3/4.2 text; (c) whether environment-matrix-non-empty should be a `sample_set` rule or belongs to the report contract's separate accessibility-support-baseline field (not directly seen in the `sample_set` row text I grepped).
