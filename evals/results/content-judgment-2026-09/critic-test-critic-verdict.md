# test-critic (opus) verdict on the a11y-content-judgment eval lane — 2026-09-02, verbatim

# VERDICT: REVISE

The instrument is better built than most in this repo — blind authorship with provenance, freeze guards, receipted overrides, pre-registered calibration, full gate registration. But the headline number it will produce (must-`no` detection) is confounded, and the A/B rests on two rows. Both are disclosure/design fixes, not rebuilds.

## CRITICAL

**1. `flags` makes R1 solvable without judgment.** All 21 must-`no` rows carry ≥1 heuristic flag; 14/19 must-`yes` carry none. Verified across all six `fixtures/*.metadata.yaml` joined to `input_rows` — e.g. `heading_generic` on both `no` headings (`HEADING-WA-e180f996ca`, `-29d24d1db5`), `alt_is_filename`, `img_missing_alt_attr`, `title_shared_by_3_views`, `field_unlabeled_placeholder-only`. The policy "flag → no" scores R1 21/21 in **both** arms. Only 5 must rows are flag-discriminating (`LINK-CO-d03461d186`, `IDENT-CO-2c687abd06`, `IDENT-PA-271f5ae86e`, `LINK-LI-33337c9396`, `LINK-LI-dcd46c10cc`) — all on the clean side. The instrument measures flag-trust calibration, not defect detection. **Fix:** state in README §Scoring that R1 is fully flag-predictable and is not evidence of judgment; report "discriminating-row score" (the 5) as the headline; or plant ≥1 unflagged defective row per fixture.

**2. The A/B prices two rows.** Baselines run on `link-purpose-cards` and `images-role-routing` (README:83–85). `images-role-routing` has **zero** flagged must-`yes` rows — its entire clean side is answerable by "no flag → yes". So the whole rubric-vs-no-rubric contrast reduces to `LINK-LI-33337c9396` (in-sentence "Learn more") and `LINK-LI-dcd46c10cc` (`aria-label`led icon link). Two rows × 2 draws cannot support any A/B claim. **Fix:** move baselines to `link-purpose-cards` + `identification-across-views` (which has the lane's cleanest design: `same_href_multiple_names` on both sides, `IDENT-PA-271f5ae86e` yes vs `-9bf8bba533`/`-63040493f3` no), and pre-commit that the A/B is reported only over discriminating rows.

## MAJOR

**3. Overrides removed exactly the diagnostic rows.** `clean-control/overrides.yaml` demotes `LINK-CO-26172863dc` to calibration because "Blind author marked a PDF link … clean (H30); the rubric rules it no." Same for `LINK-LI-a73c6c9f68` and `LINK-LI-5deb85f217`. These three are the only rows where the rubric's conventions contradict the public technique — i.e. the only rows that could catch the rubric over-flagging. Demoting them makes rubric-convention over-flagging structurally undetectable. The `never promote to must` guard is real (`map_expectations.py:228`) but nothing guards demotion, and the schema permits verdict flips — two occurred (`LINK-HE-92d4a96b2f`, `IMAGE-LI-e4d6e5fc60`: mapped `yes`, overridden to `no`; both landed at calibration so status is unaffected). **Fix:** keep the three as must-`yes` with `unsure_ok: true` under an explicit "rubric-convention conflict" label, or add a guard refusing `expected` changes and log demotions as a named count in the README.

**4. Non-independence undercuts the row counts.** `id-links` (6), `card-learnmore` (5), `bare-site-title` (3) — 14 of 40 must rows sit in 3 pattern groups that R7 requires to move together. Effective N ≈ 25, and rows within a fixture share one draw. "No false alarm observed in 2 draws" over 19 clean rows bounds the per-row FA rate only at roughly ≤15% (95%, and that assumes independence it doesn't have). **Fix:** state the bound numerically rather than as "no false alarm observed"; the third-draw-on-disagreement rule is adequate as an instability detector and README:152 correctly refuses the stability claim — keep that wording.

**5. Calibration is partly tautological.** `calibrate.py:51` builds honest rationales from `m["loses"][0]`, so R6 cannot fail in the honest case; `:53` truncates to 25 words, so C3's cap cannot fail. R7 fires in no calibration case and no smoke case (`smoke_scorers.sh:416–452`). R4 is exercised only by `cj-meta.yaml`, never by a real fixture (all six have empty `fabricated_tokens`). So 35/35 CLEAN certifies C1/C2/R1/R2/R5 wiring plus metadata self-consistency — not R4/R6/R7. **Fix:** add a `regression` case (rationale with no `loses` phrase → WARN) and a `split-group` case (one `card-learnmore` row dissenting → WARN); label the README's "35/35" with which checks it actually covers.

**6. Two planted defects a careful human would pass.** `HEADING-WA-e180f996ca` "Overview" and `-29d24d1db5` "Details" are must-`no`, `unsure_ok: false`, ref G130. Their sections (`reports.html:18–26`) genuinely are an overview and details; G130 asks headings to describe topic *or purpose*. A careful judge answering `unsure` or `yes` FAILs the fixture. **Fix:** `unsure_ok: true` on both, or move to calibration.
