# Critic standalone v2 — frozen measurement protocol

Condition ID: `critic-standalone-v2-202610`. This is a new condition, not a
reinterpretation of the completed `neutral-H1-blind-no-features-202610` run.
It uses the concise `system.md` and the repaired fixture source. The manifest
records the actual source HEAD, every rendered prompt and condition/source hash.

## Scope and eligibility

Native local requests are stateless, temperature 0.3, context 32768, output
budget 16384, native default reasoning, deadline 1800 seconds. Other sampler
and backend defaults remain recorded limitations; no cross-backend speed claim.
Use a neutral H1, strip the answer key and explicit feature section, retain code
and stated behavior. Code/prose identifiers remain: not complete semantic blinding.

A critic review is eligible only after uncontaminated qualified execution,
completed native stop, nonempty final response and one canonical verdict.
At most three scored attempts, only for empty-stop responses. Preserve every
attempt. Errors, LENGTH/clipping, nonanswers and format failures are distinct;
unstarted/interrupted cases remain UNMEASURED. Do not silently count substantive
format failures as absent knowledge. Legacy keyword scores are descriptive only.

## Fixed screen and advancement

The ten screen fixtures are unchanged. The five credited targets remain:
1. Form field errors lack programmatic input association.
2. Form summary lacks announcement or an intentional focus alternative.
3. Toast feedback lacks programmatic announcement (one defect).
4. Tooltip description is unavailable on keyboard focus.
5. Tooltip trigger lacks a programmatic description relationship.

Independently adjudicate quoted code and user impact for each hit and every
alleged substantial defect. Extra findings cannot inflate the fixed numerator.
The relative legacy 15-item score is not an advancement gate. Optional regions,
redundant live attributes and unprovided page structure are not mandatory defects.

A candidate advances only with at least 4/5 credited targets, all ten eligible
screen reviews, a complete same-condition control, and at least one reviewed
CLEAN verdict of ACCEPT/ACCEPT-WITH-RESERVATIONS without invented blocking findings.
Review proposed fixes for introduced barriers. Detection alone cannot justify
adoption. Stop at an explicit failed gate; do not infer failures for unrun cells.

## Reviewed CLEAN calibration scope

Only these four repaired controls are admitted in this condition:
button-skip-link-clean, interactive-dropdown-clean, modal-complete-clean,
search-results-dynamic-clean. Their source/browser checks cover named widget
contracts and states, not whole-page or universal browser/AT conformance.
Require independent final acceptance before labeling the repaired cohort ready.
Other legacy CLEAN fixtures remain outside this condition until reviewed.

For viable candidates, use three draws on each of these four controls. Draws
within one fixture are dependent; report verdicts, invented findings, misses and
repair quality separately, with explicit fixture/draw denominators. The seven
established bug-report fixtures retain their own skill/structure contract; no
critic Verdict requirement is imposed on bug reports. Further expanded suites
require a concrete selection advantage and separately reviewed inputs.

## Custody

Historical byte verification checks hashes only and never grants resume authority.
Execution also requires current HEAD, supplemental/scorer/condition sources and
fixture inputs to match the selected freeze. A changed live source fails closed.
Never hand-edit old freezes, seals, receipts or adjudications. New output roots
are mandatory; an existing or partial cell cannot be overwritten. Preserve
shared-service ownership and native identity/residency evidence.
