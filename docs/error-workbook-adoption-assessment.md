# Error-Workbook (XLSX) Builder Adoption Assessment

**Decision (2026-09-03, PT-18):** promote the *pattern* of an engagement's XLSX findings-workbook builders into a generalized reference script under the `bug-reporting` skill — [`.claude/skills/bug-reporting/references/build-error-workbook.mjs`](../.claude/skills/bug-reporting/references/build-error-workbook.mjs), mirrored byte-for-byte into `.agents/`. This is a **format boundary**, not an external-tool adoption: the workbook is one more serialization of the skill's existing `AccessibilityIssue` JSON schema, the way the Markdown template and EARL are. Nothing is vendored. The one runtime dependency, `exceljs@4.4.0` (MIT), is a routed peer dependency installed in the consuming project and exact-pinned there — never in this repository, the same boundary as `playwright`/`@axe-core/playwright` for `baseline-url-scan.mjs` and `@guidepup/virtual-screen-reader` for the component-assertion lane.

Disposition trail: `docs/plans/2026-09-02-promotion-candidate-dispositions.md` row PT-18 (**DEFER(wave 2; user-queued)**, reason class *scope*, scope fixed by the user as "`bug-reporting` reference script, routed exact-pinned peer dep, never vendored; adoption note on the format boundary"). Tier-4 items carry no second-reproduction clause — the ledger's gate for a format is *generalization + adoption boundary + user approval* — but the standing pre-check for routed instruments (survey maker and community first) applies and was run: § "Library choice".

## What was adopted

**The pattern, not the code.** Both engagement builders (a first-generation per-site "accessibility errors" workbook, 803 lines, and a second-generation interim tracker pair, 407 + 64 lines) import `@oai/artifact-tool` — a library private to the Codex runtime that is not on the public npm registry (`registry.npmjs.org` → `Not found`, checked 2026-09-03). Not one line of either script runs outside that runtime, so, as with PT-03, the reference script is a fresh build of the *shape* the engagement proved useful:

- **Schema fields as a fixed column order** in a defined table with a header row (`Findings` sheet). Text-formatted ID and SC columns so `1.4.3` and `EX-a3f1b2c4` survive Excel's auto-typing. No merged cells.
- **Owner-fillable triage columns** with a dropdown (`Owner`, `Remediation status`, `Notes`). The first-generation builder shipped these with an explicit "do not infer resolution from a PASS gate" note; that note survives as the `Read Me` triage text.
- **Provenance on the workbook itself** (`Read Me`: source file, SHA-256, byte size, row count, generator, peer-dep pin) so a workbook can be tied back to the exact input it was built from.
- **Live formulas with cached results** (`Summary`: COUNTIF by severity, by WCAG SC, by remediation status) rather than baked numbers, so the client's own edits keep the rollup current in Excel.
- **A read-back verifier** (`--verify`). The second-generation pair shipped a separate verifier that scanned every cell for Excel error strings and counted formulas; the reference script keeps that and adds what the evaluation-report contract requires of any generated deliverable that carries counts (`docs/a11y-evaluation-report-contract.md`, "verified cell-by-cell against the known totals in the evidence it aggregates"): finding cells compared cell-by-cell against the input's serialization; the defined table's span checked against the row count; every `Summary` cell checked **by position** — label, formula, and, for finding counts, cached result — so a shrunk range (the under-count class the contract names), a swapped pair of rows, or a stray formula is drift even when the same formula/result pair exists elsewhere on the sheet; and ten of the fifteen `Read Me` fields (all but title, product, timestamp, and the two file-name rows) recomputed from the input, SHA-256 included.

**Fail-fast input validation** at the boundary (exit 2, rows listed): the skill's six required fields must be present and non-empty (`N/A` is an honest value; absence is a defect), `severity` must be on the skill's four-value scale, `wcag_sc` must be `x.y.z` or `N/A`, `instance_id`/`pattern_id` must match the skill's `PREFIX-8hex` shape and `instance_id` must be unique, `baseline_test` must match the web-test ID pattern, and no serialized cell may exceed Excel's 32,767-character limit — refused, never silently truncated.

**Unknown keys are reported, not passed through.** Keys outside the schema are counted and listed on `Read Me` ("Input keys not serialized"). The column set is closed so the workbook cannot become a de-facto schema by accretion — the same reason the report contract refuses invented field names. `finding_id` is the single column beyond the schema, because the skill's own EARL/ACR paragraph asks reports to carry it. Two values are normalized and nothing else is altered — `severity` lower-cased, an `n/a` SC written `N/A` — and the `Read Me` carries a `Normalization` row saying exactly that.

## What was NOT adopted, and why

- **`@oai/artifact-tool`** — not public; nothing to route to. Its `SpreadsheetFile.importXlsx` / `workbook.render(... format: 'png')` preview rendering has no public-library equivalent in `exceljs`; the PNG-preview verification step from the second-generation verifier is therefore **dropped**, and visual review of a built workbook stays a human step (open it).
- **The second-generation "W3C tracker" column set** (`WCAG Success Criteria`, `Defect Summary`, `Recommendation`, `User Impact`, `Disability Type`, `Status`, `Defect Link`, …). Those headers matched a client-supplied tracker template, and the rows they carried were *operation* outcomes with every WCAG column filled "Not assigned" — a deliberate non-assertion under that engagement's evidence rules. That is an engagement artefact, not a reusable finding serialization.
- **The ICT-baseline tracker workbook** (62-test inventory + coverage rollup). Its data is the a11y-test crosswalk (`.claude/skills/a11y-test/references/ict-baseline-crosswalk.yaml`), and its claim ("coverage describes test-system design, not a product result") belongs to declared-508 audit scope. Serializing the crosswalk to XLSX is a different, un-requested item; if wanted it is a separate scope call, not a silent extension of this script.
- **A retest-outcome dropdown** (`Not Retested / Pass / Fail / CantTell`, present in the first-generation builder). A retest outcome is an evidence-bearing claim; a11y-test's retest classification and verification-evidence contract put it with the auditor, produced from class-matched evidence, not with the receiving team's spreadsheet. The status column keeps `Ready for Retest` as the client's signal and `Resolved` as their workflow state; closure is the auditor's re-export, and the `Read Me` says so in plain text.
- **Hard-coded expected totals** (the first-generation builder asserted `expected: { issues: 14, gates: 33, … }` per site). Generalized into `--verify`'s recomputation from the input, which is the same check without the per-engagement constants.
- **Palette/branding, product names, and per-site configuration** — engagement identifiers; excluded by the client-reference policy and by scope.

## Boundary — what the workbook is and is not

- **It is a serialization of findings.** Each row is one filed finding at the skill's severity, which is impact on people. It carries no criterion-level PASS/FAIL, asserts no conformance, and is not an Accessibility Conformance Report — route ACR/VPAT work to `acr-reporting`, which takes the *evaluation report* (`docs/a11y-evaluation-report-contract.md`), not this workbook, as input. Conformance outcomes and impact severity stay orthogonal (`docs/a11y-orthogonality-register.md`); the `Summary` counts are counts of findings, never a score.
- **A short or empty list is not evidence of conformance.** The `Read Me` claim-boundary text says exactly that, on the sheet a client opens first.
- **`--verify` proves the finding data, not the triage.** Triage columns are excluded from comparison by design, so the check still holds after the client has filled them; it will flag any edit to a finding cell (a changed severity, a deleted row), which is the intended use when a workbook comes back.
- **`baseline_test` is pattern-checked, not membership-checked.** The script runs standalone in a consuming project and cannot see `docs/ict-baseline-test-id-manifest.yaml`; membership stays the bug-report scorer's job.
- **Spreadsheet-accessibility basics only.** Named sheets, a header row in a defined table, no merged cells, severity conveyed as text with fill as a secondary cue, text-formatted ID columns, frozen header row and first two columns (what a magnification user loses first is the row's identity), a document title/subject/description in the file properties, and the triage boundary as the status cell's own input message rather than three sheets away on `Read Me`. This is not a claim that the workbook meets any accessibility standard for documents; it is the set of choices that avoid the known screen-reader hazards (merged cells, colour-only meaning, untyped IDs).
- **No model in the loop.** The script is deterministic; there is no eval-lane row to draw and no detector caveat. Its falsifiable check is the mutation-canary set below (PT-21 folded), not a BUG/CLEAN fixture pair.

## Library choice

Standing pre-check for routed instruments, run 2026-09-03: [`evals/results/promotion-eval-2026-09/memos/1.9-xlsx-maker-skill-survey.md`](../evals/results/promotion-eval-2026-09/memos/1.9-xlsx-maker-skill-survey.md) (skills.sh, npm, GitHub, and vendor docs, each with a positive control and a zero-hit log). Result: **nothing to reuse.** The only open-source vendor exporter that emits XLSX is IBM's `accessibility-checker` (Apache-2.0; its `outputFormat` option accepts `xlsx` — confirmed on the package README, latest 4.0.33), and it is bound to IBM's own result schema, not this skill's. Every other vendor surveyed (axe DevTools, Accessibility Insights, pa11y, Alfa, Lighthouse, WAVE, the WCAG-EM Report Tool, OpenACR) tops out at CSV/JSON/HTML/EARL/YAML. Three unpackaged GitHub project trees combine axe-core with ExcelJS directly; none is installable as a library or skill. No accessibility MCP server offering XLSX export was found.

Library tier, independently re-verified against `registry.npmjs.org`, `api.npmjs.org`, and the GitHub advisory database on 2026-09-03:

| Library | Version | Published | License | Downloads/mo | Advisories affecting the current version |
|---|---|---|---|---|---|
| `exceljs` | 4.4.0 | 2023-10-19 | MIT | 55.3M | none (one medium XSS advisory, patched in 1.6.0) |
| `xlsx` (SheetJS, npm line) | 0.18.5 | 2022-03-24 | Apache-2.0 | 50.2M | **two HIGH, unpatched on npm** — ReDoS (GHSA-5pgg-2g8v-p4x9, fixed only from 0.20.2) and prototype pollution (GHSA-4r6h-8v6p-xvw6, fixed only from 0.19.3); maintained builds ship from SheetJS's own CDN, not npm |
| `write-excel-file` | 4.1.1 | 2026-06-08 | MIT | 2.8M | none found; write-only, so it cannot back `--verify`'s read-back |
| `xlsx-populate` | 1.21.0 | 2020-03-01 | MIT | 0.9M | none found; unmaintained since 2020 |

`exceljs` is the pick: MIT, the widest adoption, reads as well as writes (the verifier needs read-back), and no advisory touches 4.4.0. Its own last release is October 2023 — a watch item in the reopen triggers, not a blocker. **Not verified:** whether IBM's exporter could be adapted to this schema (its source was not read); adapting a schema-bound exporter was judged a larger commitment than a standalone script against a documented library, but that is a judgment, not a measurement.

## Validation performed

Run 2026-09-03 from a scratch project outside this repository (`node v24.19.0`, `exceljs@4.4.0` installed there only) against a five-row synthetic input ([`evals/results/error-workbook-2026-09/findings.json`](../evals/results/error-workbook-2026-09/findings.json): three rows with stable IDs, a manual finding with `rule_id: N/A` and a `finding_id`, a best-practice row with `wcag_sc: N/A`, one declared-508 `baseline_test`, and two keys outside the schema). The script under test was byte-identical to the committed file (SHA-256 in the receipt). Receipt, verbatim: [`evals/results/error-workbook-2026-09/canaries.md`](../evals/results/error-workbook-2026-09/canaries.md); the summary table is in that directory's README.

Rev 2 (the committed script, after the critic fold): 29 canary rows across 21 sections, all PASS; rev 1 (pre-fold script) 21/21 on the first thirteen. Grouped by what they exercise:

- **Clean round trip** (C1): build, then `--verify` → exit 0, 15 formulas.
- **Drift detection** (C2 deleted row, C3 changed severity cell, C4 formula range shrunk by one row with its cached result kept, C5 `#REF!` injected, C7 verified against a different input, C11 Summary sheet removed, C12 Read Me row count tampered): each exit 1, each naming the cell, sheet, or field. C4 is the report contract's under-count class, caught at the formula text rather than at the number — a shrunk range reports three lines (range end, unknown formula, missing expected formula), all pointing at the same cell.
- **Relaxation** (C6): every triage column filled on every row → exit 0. The one canary that must pass *clean*; it is what makes `--verify` usable after a client returns the sheet.
- **Refusals** (C8a–i): duplicate `instance_id`, missing required field, off-scale severity, malformed `wcag_sc`, over-limit cell, empty input, wrong output extension, unknown flag, missing input file → each exit 2, each naming the row and field where one exists.
- **Read-back facts** (C9 ignored keys listed on Read Me, C10 SC rollup order and counts with `N/A` last, C13 the status dropdown's list validation present).
- **Critic-fold canaries** (rev 2 only): C14/C15 Summary rows swapped with and without their labels, C16 a recomputable Read Me field tampered, C17 the Summary boundary line altered, C18 the defined table removed — each exit 1 naming the cell; C19 `--verify` against an invalid input → exit 2; C20 the status cell's input message and C21 the workbook title read back as written.

Both battery runs were by a subagent; the coordinating session re-ran C4 and C6 (rev 1) and C14 and C18 (rev 2) live and reproduced all four.

**Critic round (2026-09-03, receipts in `evals/results/error-workbook-2026-09/critic-rounds.md`).** `a11y-critic` (opus) ACCEPT with two MAJOR placement fixes — the claim boundary was only on `Read Me` while `Summary` is the sheet a conformance outcome could be read from, and the status dropdown carried no input message — both folded (a boundary line in `Summary!A1`; the triage note as the cell's prompt). `harsh-critic` (sonnet) REVISE with one real MAJOR: `--verify` matched `Summary` formula/result pairs by content, so swapping two rows' cells passed clean (reproduced by the critic). Folded by verifying the sheet by position from the same layout the build writes; the battery was re-run against the revised script with the swap and four further canaries added (rev 2 receipt). The critic also confirmed empirically that exceljs writes `=`/`+`/`-`/`@`-leading strings as shared-string cells with no formula element, so the formula-injection class does not apply on the build side.

**Not validated:** rendering in Excel, Numbers, LibreOffice, or Google Sheets (no renderer in the toolchain — the PNG previews went with `@oai/artifact-tool`); the workbook's behaviour under a screen reader; inputs larger than five rows (no performance claim); formula recalculation by a spreadsheet application (cached results are checked, evaluation is not); `baseline_test` membership in the manifest.

## Reopen triggers

1. **A second engagement wants a different column set.** The right move is a `--columns` allow-list over the schema, not passing unknown keys through. Until then the closed set stands.
2. **A consumer needs the ICT-baseline or WCAG-EM sample-set serialized.** Separate scope call; different input contract (crosswalk YAML / report contract), different claim boundary.
3. **`exceljs` publishes a security advisory affecting the write path, or a maintained SheetJS line returns to npm.** Re-run the library survey; the pin is exact so a bump is a deliberate, receipted change.
4. **A client returns a workbook with edited finding cells.** Not a reopen — that is `--verify` doing its job — but the first live instance should be recorded beside the canaries as the first non-synthetic drift catch.
