## Post-gate addendum (2026-08-06, main session — operator prompted)

Operator asked what options Vimeo actually provides. Deeper probe partially corrects the Vimeo picture:

- The earlier "docs list url, width, maxwidth, byline, title, portrait, color, callback" claim came from an incomplete search snippet. The real oEmbed argument table (developer.vimeo.com/api/oembed/videos) is long and includes `audiotrack` (initial audio track by language code) and `texttrack` (initial caption track), plus `cc`, `chapters`, `controls`, `colors`, `dnt`, quality options, etc.
- Verified empirically: Vimeo's oEmbed **passes recognized params through** into the returned embed src (`texttrack=fr` → `&texttrack=fr`; `audiotrack=fr` → `&audiotrack=fr`; `cc=false` → `cc=0`). Unrecognized params (`locale`) are dropped, byte-identically. The MR's mechanism is therefore sound for Vimeo; it used a nonexistent parameter.
- The critic's UI-chrome conclusion stands and is now stronger: `?locale/lang/language/hl/texttrack=fr` on `player.vimeo.com` all leave the player at `lang="en"`; an `Accept-Language: fr-FR` header flips player config to `"lang":"fr-FR"`. Browser-detected only; not settable server-side.
- New constructive path recorded in packet: `texttrack`/`audiotrack` matched to page language via the same alter hook — a content-language enhancement outside this issue's SC 3.1.2 chrome-language scope.
